# 需求

## 1. 背景

eMMC 用户区通常用 GPT 描述分区。一套可下载的板级镜像并不只是一颗整盘镜像，而是：

- 分区表（名称、类型、起始、大小、属性）
- 每个分区可选的镜像文件（boot、system、userdata 等）
- 与这颗 eMMC 相关的元数据（容量、扇区大小、对齐、板卡或产品标识）

现有厂商工具把这些信息绑在各自的打包格式和下载协议上，不能跨 Windows、macOS、Ubuntu 共用，也很难只改一张分区表而不碰到整盘镜像。et 要做的是一个与具体 SoC 下载协议解耦的编辑器：先把“包”定义清楚并能够编辑，再把下载做成可替换的后端。

## 2. 用户与场景

**用户**：板级固件工程师、系统集成工程师、产线下载脚本的维护者。默认单人在本地编辑一个包，不做多人同时编辑。

**主场景**

1. 为一块已知容量的 eMMC 新建包，按顺序添加分区并填入已有镜像。
2. 打开已有包，调整某个分区的大小或替换它的镜像，保存后交给下载环节。
3. 打开包时立刻看到重叠、超出容量、镜像缺失或镜像大于分区这类错误，而不是下载失败后才发现。

**非目标用户场景**：在工具里修改 ext4/FAT 文件内容、挂载分区、编辑单文件的十六进制内容、同时管理多块板卡的量产数据库。

## 3. 范围

### 3.1 第一期要做

- 新建、打开、保存 eMMC 镜像包。
- 包内包含分区表、各分区的镜像文件（可以没有）、元数据。
- 编辑分区表：增加、删除、重命名、修改大小、更换镜像文件。
- 自动排布与保存前校验。
- Windows 7 SP1 x64 及以上、macOS、Ubuntu 22.04 及以上使用同一套代码与同一份包格式。不做 32 位 Windows 版本。

### 3.2 第一期不做

这些能力会影响架构，但实现放到后面的里程碑。需求里写明，是为了避免第一期把接口做死。

- 把包刷进 eMMC（USB 下载、块设备写入、fastboot）。
- 解析或生成 Android sparse、生成整盘 raw 镜像、导入导出 GPT 二进制。
- 编辑镜像内部文件系统。
- Boot1 / Boot2 的烧录。格式里为它们预留可选字段，第一期界面不暴露。RPMB 不进入包格式。
- 账户、云同步、权限、产线统计。
- 撤销以外的历史版本管理。第一期提供会话内撤销/重做。

## 4. 概念

**镜像包**：磁盘上的一个目录，扩展名约定为 `.etpk`。目录里有一份 `manifest.json` 和可选的 `images/`。这是编辑时的唯一工作格式。

**分区**：用户区里的一条逻辑分区。第一期不区分“只存在于 GPT 的分区”和“带镜像的分区”；镜像是分区的可选附件。

**自动排布**：分区按列表顺序放置。未手写起始地址的分区，起点取“上一分区结束位置向上对齐”后的结果。第一条分区还要让过主 GPT 保留区。

**固定起始**：分区可以手写 `startBytes`。这种分区不参与顺延；别的分区改大小时它留在原地。重叠由校验报错，工具不自动挪走它。

**扇区**：逻辑扇区大小来自元数据，默认 512 字节。界面可以用 MiB/GiB 输入，核心库一律用字节整数运算。

## 5. 功能需求

优先级：P0 是第一期验收项，P1 是紧随其后的编辑完善，P2 是下载与镜像生成。

### 5.1 镜像包

| 编号 | 优先级 | 需求 |
| --- | --- | --- |
| FR-PKG-01 | P0 | 新建包。用户给出包名称、用户区容量、扇区大小。工具创建目录、`manifest.json` 和空的 `images/`。默认对齐 1 MiB，分区列表为空。 |
| FR-PKG-02 | P0 | 打开包。用户选择 `.etpk` 目录。工具读取 manifest，检查格式版本，核对镜像相对路径没有逃出包目录。 |
| FR-PKG-03 | P0 | 保存。只原子替换 `manifest.json`。分区镜像在“指定镜像”时已经复制进 `images/`，保存不重写镜像字节。 |
| FR-PKG-04 | P0 | 关闭或打开另一包时，若有未保存修改，必须先确认。 |
| FR-PKG-05 | P0 | 另存为。把整个目录复制到新位置，包含已纳入包内的镜像。 |
| FR-PKG-06 | P1 | 将包导出为单个 zip，便于拷贝；导入时还原成目录再编辑。 |
| FR-PKG-07 | P1 | 在元数据中编辑产品名、说明、容量、扇区大小、对齐。容量或扇区大小变化后立即重新校验。 |

新建时容量必须是扇区大小的整数倍，且大于主 GPT 与备份 GPT 占用的空间。扇区大小第一期允许 512 或 4096。

### 5.2 分区表编辑

| 编号 | 优先级 | 需求 |
| --- | --- | --- |
| FR-PT-01 | P0 | 增加分区。默认追加到列表末尾，名称在包内唯一，大小由用户给出且为扇区整数倍。起点默认自动。空间不够时拒绝添加并说明原因。 |
| FR-PT-02 | P0 | 删除分区。删除后，后续自动排布分区按新顺序重新计算起点；固定起始分区不动。分区对应的镜像文件从 `images/` 删除。 |
| FR-PT-03 | P0 | 重命名。名称在包内唯一。镜像文件名使用分区 id，不随显示名改变。 |
| FR-PT-04 | P0 | 修改大小。单位在界面上可用字节或 MiB，写入 manifest 的是字节。改大小后重新计算后续自动排布分区的起点。 |
| FR-PT-05 | P0 | 更换镜像。用户从文件系统选择一个文件，工具把它复制到 `images/<partition-id>.img` 并记录相对路径。允许清除镜像。更换时覆盖该分区的旧文件。 |
| FR-PT-06 | P0 | 列表展示每一行的名称、类型、起点、大小、镜像文件名、该行校验状态。起点标注“自动”或“固定”。 |
| FR-PT-07 | P1 | 调整分区顺序。顺序就是自动排布的顺序。 |
| FR-PT-08 | P1 | 把分区改为固定起始，或清除固定起始恢复自动排布。 |
| FR-PT-09 | P1 | 设置 GPT 类型（预设或原始 GUID）和属性位。第一期类型使用默认值 `linux-filesystem`，界面只读展示。 |

名称限制与 GPT 一致：非空，UTF-16 编码后不超过 36 个码元。允许字母、数字、`-`、`_`、`.`。其他字符第一期直接拒绝，避免各下载器对 Unicode 分区名行为不一致。

### 5.3 校验

校验结果跟文档一起返回，界面在分区表旁列出。存在错误时仍允许保存（工程师可能暂时存一个不完整的包），但窗口标题或状态栏必须标明“含错误”。另存为和之后的下载必须可以单独要求“无错误才继续”；第一期没有下载，保存本身不因为校验错误而失败。

| 编号 | 优先级 | 规则 |
| --- | --- | --- |
| FR-VAL-01 | P0 | 分区之间、分区与主/备 GPT 保留区之间不得重叠。 |
| FR-VAL-02 | P0 | 任一分区必须完全落在用户区的可用 LBA 范围内。 |
| FR-VAL-03 | P0 | 大小、起点（若固定）必须是扇区大小的整数倍；自动排布的起点必须满足对齐。 |
| FR-VAL-04 | P0 | 名称唯一且符合 FR-PT-03 的字符和长度限制。 |
| FR-VAL-05 | P0 | manifest 引用了镜像时，文件必须存在、是常规文件、相对路径解析后仍在包目录内。路径越出包根时拒绝打开，不读取包外文件。 |
| FR-VAL-06 | P0 | 镜像的文件字节数大于分区大小时记为错误。 |
| FR-VAL-07 | P1 | 镜像字节数不是扇区整数倍时记为警告。 |
| FR-VAL-08 | P2 | 识别 Android sparse。用展开后的大小参与 FR-VAL-06，而不是用压缩文件大小。 |

第一期不解析 sparse。一个展开后超出分区、但文件本身更小的 sparse 镜像会通过 FR-VAL-06。这个限制写在校验说明里，避免被当成整盘容量校验已经完成。

### 5.4 撤销

| 编号 | 优先级 | 需求 |
| --- | --- | --- |
| FR-EDIT-01 | P0 | 会话内撤销和重做分区编辑与元数据编辑。栈只在内存中，保存不清空栈，关闭包清空栈。 |
| FR-EDIT-02 | P0 | 指定镜像和删除分区会改动 `images/` 里的文件。撤销必须把文件副作用一并恢复。实现上先把被替换或被删除的文件移到包内临时目录，会话结束或保存策略确定后再清理。 |

### 5.5 下载（后续）

第一期不实现。这里固定后续能力要满足的约束，供架构预留。

| 编号 | 优先级 | 需求 |
| --- | --- | --- |
| FR-DL-01 | P2 | 下载器只通过分区 id 流式读取镜像，不把镜像装进文档对象。 |
| FR-DL-02 | P2 | 至少一种本机后端：把用户区写到块设备（Linux）或写出一张用户区 raw 镜像（全平台）。 |
| FR-DL-03 | P2 | SoC 专用协议（Rockchip、fastboot、高通 EDL 等）做成可选后端，不放进核心库的必选依赖。 |
| FR-DL-04 | P2 | 下载前拒绝带有校验错误的包。 |

## 6. 非功能需求

| 编号 | 需求 |
| --- | --- |
| NFR-01 | 三个桌面系统同一仓库、同一套界面构建。Windows 最低运行版本是 Windows 7 SP1 x64。不维护第二套界面，也不做 32 位 Windows 版本。 |
| NFR-02 | 打开含数 GB 至数十 GB 镜像的包时，内存不随镜像大小增长。文档模型只保存路径、长度和可选校验和。 |
| NFR-03 | 保存 manifest 使用临时文件加原子改名，避免写到一半断电后包无法打开。 |
| NFR-04 | 指定镜像时的复制可以处理大于 4 GiB 的文件（ZIP64 留到导出功能；工作格式是目录，不受 zip 32 位限制）。 |
| NFR-05 | 核心库不链接 GUI，可以用单元测试覆盖布局、重叠、GPT 保留区和路径逃逸。 |
| NFR-06 | 第一期界面可在 1280×800 下完成分区表编辑，不依赖网络。 |
| NFR-07 | 包格式带 `formatVersion`。不认识的主版本拒绝打开，不静默改写。 |

## 7. 第一期验收

在 Windows 7 SP1 x64、macOS、Ubuntu 22.04 上分别完成下面的路径即视为第一期完成：

1. 新建一个 16 GiB、512 字节扇区的包。
2. 添加 `boot`（64 MiB）和 `system`（2 GiB），为 `boot` 指定一个不大于分区的本地文件。
3. 把 `system` 加大到超过剩余容量，界面出现错误；再改回可容纳的大小，错误消失。
4. 重命名 `boot`，保存，重新打开，分区名、大小、起点和镜像都在，镜像内容与源文件一致。
5. 删除 `system` 后撤销，分区和它的镜像引用恢复。
6. 把镜像路径改成包外路径的操作无法通过工具完成；手工把 manifest 里的镜像改成包外路径时，打开失败，且不读取该文件。
