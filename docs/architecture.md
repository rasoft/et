# 架构

## 1. 结论

et 分成三层：

1. **`et-core`**：无界面的 Rust 库。负责包格式、分区排布、校验、镜像文件的复制与删除。
2. **应用命令层**：仍在 Rust 里。把一次操作变成对 `et-core` 的调用，维护当前打开的包、脏标记、撤销栈，并通过 C ABI 把结果交给界面。
3. **界面**：Qt 5.15 Widgets（C++）。分区表、元数据表单、校验列表、文件对话框。

选定这个组合，是因为第一期的难点不在控件样式，而在大文件、二进制布局，以及要在 Windows 7 SP1 x64、macOS、Ubuntu 上跑同一套程序。分区算术和包读写留在 Rust；Windows 7 跑不了当前的 WebView2，所以界面用 Qt 5.15，不用 Tauri。

```
界面 (Qt 5.15 Widgets)
    编辑命令 / 当前文档 + 校验列表
应用命令层 (Rust, C ABI)
    打开的包、脏标记、撤销栈、文件对话框路径
et-core (Rust)
    manifest、布局、校验、镜像复制
磁盘上的 .etpk 目录
```

界面不自行计算起点和重叠。每次编辑后，核心库返回新的分区视图（含计算后的起点）和校验列表，界面整表刷新。

## 2. 选型

### 2.1 语言与界面

| 方案 | 评价 |
| --- | --- |
| Rust 核心 + Qt 5.15 Widgets | **采用。** Qt 5.15 的目标平台包含 Windows 7、macOS 和 Linux，一套界面代码即可。布局和包读写留在 Rust，经 C ABI 交给 Qt。Windows 只交付 64 位。 |
| Rust 核心 + Tauri 2 + React | 不采用。Tauri 2.12 起不再支持 Windows 7，并把 Rust 最低版本抬到 1.90。2.11 是最后一版还能在 Windows 7 上工作的发布，而且要自行准备旧的 WebView2 固定运行时；现行 WebView2 安装器在 Windows 7 上会因缺少 `GetPackagesByPackageFamily` 失败。这条路官方已经停掉。 |
| Rust + egui | 不采用。当前 eframe 默认走较新的 Rust 和 wgpu，没有 Windows 7 运行承诺。为了 Windows 7 再钉一套过时的 egui，界面还得手写表格和对话框。 |
| Electron + Node | 不采用。最后能在 Windows 7 上运行的 Electron 22 已停止维护，安装包也大。 |
| Python + PySide2（Qt 5） | 不采用。CPython 3.9 起不再支持 Windows 7，能用的 3.8 已停止维护。打包和后续 USB 后端仍然别扭。 |
| 全部改成 C++/Qt 5.15 | 不采用。Qt 6 不能在 Windows 7 上运行，所以界面确实要用 Qt 5；但分区布局和包格式的测试仍放在 Rust 核心库，不把这部分重写成 C++。 |
| Qt 6 | 不采用。最低系统是 Windows 10 1809。 |

Qt 与 Rust 之间只过 C ABI。`DocumentView` 用 UTF-8 JSON 字符串传递，由 Qt 解析后填表。C++ 里不写第二套布局算法。JSON 文本由 Rust 分配，用配套的释放函数交还。

### 2.2 工作格式

编辑时的包是**目录**，不是单个压缩文件。分区镜像经常到数 GB，压缩包做随机替换和崩溃恢复都很差。`manifest.json` 很小，用“写入临时文件再改名”就能安全保存。镜像在用户选定的那一刻复制进 `images/`，保存不再碰这些字节。

分发用的单个 zip 放到 P1（FR-PKG-06），不作为编辑格式。

不采用的做法：

- 把镜像字节嵌进 JSON 或 SQLite。
- 以整盘 raw 镜像为编辑单位，改一个分区就要重写整盘。
- 第一期就兼容各厂商 update 镜像。导入器以后读入后转成 `.etpk`。

### 2.3 分区布局策略

核心库里的分区列表就是顺序。每条分区有必填的 `sizeBytes` 和可选的 `startBytes`。

- `startBytes` 为空：自动。起点 = 对齐(前一条的结束位置)。第一条的“前一条结束位置”是主 GPT 保留区结束处（标准 GPT 为 LBA 34 的字节偏移）。
- `startBytes` 有值：固定。工具不因为前后分区变化而移动它。

对齐默认 1 MiB，记录在元数据里。对齐值必须是扇区大小的整数倍。

可用区间：

- 用户区字节数记为 `userAreaBytes`，扇区大小记为 `sectorSize`。
- 主 GPT 保留区占用前 34 个扇区（保护 MBR + 头 + 128 项条目区）。
- 备份 GPT 占用末尾 33 个扇区。
- 可用字节范围为 `[34 * sectorSize, userAreaBytes - 33 * sectorSize)`。

第一期固定按 128 个 GPT 条目预留，不支持扩大条目区。分区条数上限 128。这与常见 eMMC GPT 一致，也让保留区大小是常数。

删除、改大小、重排之后，核心库按上述规则重算全部自动分区的起点，再跑校验。固定分区只参与校验，不参与重算。

## 3. 模块

建议的仓库布局：

```
crates/et-core/     包模型、布局、校验、磁盘读写
crates/et-cmd/      命令、撤销栈，以及给 Qt 用的 C ABI
src-qt/             Qt 5.15 Widgets 界面
docs/               设计文档
```

`et-core` 对磁盘的操作收拢在一个小模块里，其余逻辑针对内存中的文档结构和调用方提供的“文件有多大”函数做纯计算，便于测试。

### 3.1 文档模型

内存模型与 `manifest.json` 对应，外加打开时算好的派生字段（绝对路径、计算出的起点、校验项）。派生字段不写回 manifest。

分区的稳定标识是随机 UUID（`id`）。界面列表、镜像文件名、撤销记录都用它。显示名可以改，id 不可以。新建分区时生成 id。

镜像槽：

- manifest 里 `image` 为 `null`，或为相对于包根的路径 `images/<id>.img`。
- 不允许用户自由填写相对路径。更换镜像只能通过命令，由核心库复制并写入这条固定相对路径。
- 这样第一期没有“重新链接任意路径”的需求，路径逃逸面只剩手工改过的 manifest。打开时若相对路径越出包根，该分区记错误，并且不把该路径交给任何读取文件内容的接口。

### 3.2 命令

界面不直接改文档。命令集与第一期按钮一一对应：

- `create_package(dir, metadata)`
- `open_package(dir) -> DocumentView`
- `save()`
- `save_as(dir)`
- `set_metadata(patch)`
- `add_partition(name, sizeBytes)`
- `remove_partition(id)`
- `rename_partition(id, name)`
- `resize_partition(id, sizeBytes)`
- `set_partition_image(id, sourcePath | null)`
- `undo` / `redo`

P1 再加 `move_partition`、`set_start`、`set_type`。

每个修改命令返回 `DocumentView`：元数据、带计算起点的分区行、校验列表、脏标记、能否撤销。失败（例如名称非法、源镜像打不开）不修改文档，返回错误字符串。校验失败不是命令失败，见 FR-VAL 的保存策略。

### 3.3 撤销

撤销栈存放在应用命令层，不放进 `et-core` 的文档对象。每一项是“命令的逆操作”加上文件副作用：

- 更换镜像前，若 `images/<id>.img` 已存在，先移动到 `images/.trash/<op-id>.img`。撤销时再移回。
- 删除分区同理。
- 清除镜像时把文件移入 `.trash`，而不是立刻删除。

`.trash` 不写入 manifest 的分区列表。打开包时可以清空上次崩溃留下的 `.trash`。保存成功不代表可以丢掉撤销栈；只有关闭包时删除不再被栈引用的 trash 文件。

这个设计满足 FR-EDIT-02，同时避免把数 GB 镜像复制进内存。

### 3.4 界面

三个区域即可：

- 顶部：包名称、容量、扇区、脏标记、保存 / 另存为。
- 中部：分区表。行内编辑名称和大小；“添加”“删除”“选择镜像”“清除镜像”。
- 底部或侧栏：校验列表，点一条时滚动到对应分区。

界面保存最近一次 `DocumentView`，每次命令返回后整表刷新。没有打开包时不展示空表装饰数据。

文件选择用 `QFileDialog`。界面只拿到路径并交给 `set_partition_image`。Windows 7 上使用 Qt 自带的对话框，不调用只存在于更新系统里的文件选择接口。

## 4. 大文件与完整性

- 打开包：读 manifest 文本，对每个镜像做 `metadata` 级别的存在性和长度检查，不读内容。
- 指定镜像：流式复制。复制到 `images/<id>.img.partial`，完成后改名为正式文件。失败则删除 partial。
- 保存：把 manifest 序列化到 `manifest.json.tmp`，`fsync`，再改名为 `manifest.json`。
- 校验和：P1 可选字段，用流式 SHA-256，不在每次打开时强制重算。第一期 manifest 不写校验和，避免保存变慢。

## 5. 下载如何接进来

下载不进第一期，但核心库现在遵守三条约束，避免以后改格式：

1. 分区镜像永远是包内独立文件，下载器按偏移流式读取。
2. 文档模型里的容量、扇区、对齐、计算后的起点和大小足够描述用户区布局，不依赖界面状态。
3. `et-core` 不依赖具体 USB 协议。

后续在核心库旁边增加 `et-flash`（名字可改），对一种后端实现一个写入接口，例如：

- `ImageSource`：按分区 id 打开只读流，提供字节长度。
- `UserAreaWriter`：按字节偏移写入用户区，或按分区写入。

第一期的块设备后端和 raw 导出只是这个接口的两个实现。Rockchip、fastboot、EDL 各自一个实现，放在可选 feature 里，不链接进默认安装包，直到该协议真的要交付。

生成 GPT 二进制和整盘 raw 镜像属于 P1/P2 的纯函数：输入是校验通过的文档，输出是字节流。它们使用与编辑器相同的保留区和起点规则，避免“编辑器看到的布局”和“刷进去的布局”两套公式。

## 6. 错误与兼容

- manifest 不是 JSON、缺字段、`format` 不是 `etpack`、`formatVersion` 主版本不是 1：打开失败，不创建半份文档。
- 分区条数、数值溢出、容量不是扇区整数倍：打开失败。
- 镜像缺失、重叠、超出容量：打开成功，校验列表带错误。这样工程师能修好一个被手工改坏的表，而不是被拒之门外。
- 路径逃逸：拒绝打开，并指出是哪一条路径。不读取包外文件，也不进入可继续保存的编辑状态。

## 7. 测试

`et-core` 和命令层用临时目录做测试，不启动 Qt。

必测：

- 两条自动分区的起点：第一条在 1 MiB 对齐后的可用区起点，第二条紧随第一条对齐。
- 中间分区加大后，后续自动分区顺延；固定起始分区不移动，重叠被报出。
- 分区伸入备份 GPT 区域时报错。
- 128 条上限。
- 镜像大于分区、镜像缺失。
- `image` 为 `../outside.img` 时拒绝。
- 保存中断的模拟：只存在 `.tmp` 时，原 manifest 仍可打开。
- 复制镜像使用大于 4 GiB 的稀疏文件或短测试里以流式复制桩代替，断言目标长度等于源长度。

界面第一期用手工验收清单（见需求文档第 7 节），不把 GUI 自动化当作合并条件。

## 8. 构建与运行依赖

- Rust **1.77**。这是官方工具链里最后一个自带 Windows 7 支持的版本（2024-03）。三个平台的核心库和命令层都用它编译，避免出现只能在新系统上解析的依赖锁。依赖保持在 serde、serde_json 这一档，并钉住仍能在 1.77 上编译的版本。
- Qt **5.15** Widgets，C++。使用开源的 5.15 构建；需要后续补丁时用 KDE 的 Qt 5 补丁集合，不升级到 Qt 6。
- 不使用 Node.js，也不使用 WebView2。Windows 7 上没有可用的现行 WebView2 安装器。
- Ubuntu 构建机安装 Qt 5 的开发包。交付物是 `.deb`：可执行文件装到 `/usr/bin/et`，运行期依赖发行版里的 Qt 5.15 Widgets 运行库，不依赖 WebKitGTK。
- macOS 交付同时包含 x86_64 和 arm64 的通用 `.app`，并打成 `.dmg`。x86_64 使用官方 Qt 5.15.2；arm64 使用带苹果芯片支持的 Qt 5.15.2，不换 Qt 6。arm64 切片的最低系统版本是 11.0，x86_64 仍是 10.13。
- Windows 安装包的子系统版本设为 Windows 7，并在 Windows 7 SP1 x64 上做启动验收。不支持 32 位。
- 不在运行时下载分区类型数据库或协议描述。预设类型表编译进核心库。

## 9. 风险

| 风险 | 处理 |
| --- | --- |
| Rust 1.77 过旧，新 crate 无法编译 | 核心库和命令层的依赖清单保持很小，并在 CI 里用 1.77 编译。不把 Tauri、egui、新的 `windows` crate 引进来。 |
| Qt 5.15 开源补丁停在较早的版本 | 用 KDE 的 Qt 5 补丁集合。界面不使用 Qt 6 才有的控件。 |
| Windows 7 已没有微软的安全更新 | 把它当作必须能运行的目标，不把操作系统更新当作交付手段。程序自身不内嵌浏览器运行时。 |
| 工程师期望第一期就能刷机 | 路线图把 P2 分开。第一期交付物是可保存、可校验的包，不是下载器。 |
| 不同 SoC 的对齐和 GPT 保留区习惯不一致 | 对齐写入元数据。保留区第一期固定标准 GPT。若某芯片不是 34/33 扇区，以后用格式次版本增加可选字段，不改变默认。 |
| sparse 镜像被误判为“放得下” | 已在 FR-VAL-08 记为已知限制，校验文案中说明第一期比较的是文件大小。 |
